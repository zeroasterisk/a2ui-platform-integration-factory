# t3code × A2UI: 4-minute demo script

**Thesis:** MCP Apps let an agent ship you a *web page*. A2UI lets an agent ship you *data* that t3code renders itself, with any provider, in t3code's own components, with no agent code running on your machine.

All turns come from `Replay (dev)` transcripts, so the demo is deterministic and free. One live-model take is optional.

## 0:00–0:50 The gap (MCP Apps today)
1. A Codex thread calls an MCP App: an iframe card renders. Point out that it's off-theme, has a fixed height, and runs arbitrary JS in a sandbox.
2. Click its button: a **confirm dialog** appears ("this app wants to send a message").
3. Same ask on a Claude / OpenCode thread: a **plain tool row**, nothing renders (MCP Apps are Codex-only in t3code).
4. Stop the session: the app goes view-only.

## 0:50–2:30 The fill (native A2UI)
1. Ask: "triage these 3 failing PRs". The agent streams prose, then a **native card** appears in the message: a Base UI ChoicePicker per PR (retry / revert / skip), a CheckBox ("notify owners"), a TextField (note) and a primary Button "Apply".
2. Toggle light → dark: the card follows the theme instantly (same tokens as the rest of the thread). Tab through it: keyboard and focus rings work. Cmd-F finds text inside the card.
3. Click **Apply**: no confirm dialog. A **visible user message** appears carrying the exact action payload (`a2ui-action`).
4. The agent's next turn **updates the same surface** (`surfaceId`): rows flip to ✅ / ↩︎, and a summary row appears.
5. Swap the provider (Claude → Codex → OpenCode replay): identical rendering. It's just message text.

## 2:30–3:30 Why it's more trustworthy
1. "View source" on the message: ~10 lines of Express (`root = Card(...)`). It's declarative, with **no HTML and no JS**.
2. An adversarial turn (agent tries `<script>`, an unknown `Iframe(...)` component, a `javascript:` URL): it renders as a plain code block, because the catalog validator rejects it and nothing executes.
3. Every interaction is a **user-visible message in the transcript**: auditable, replayable, forkable. There's no hidden channel and no separate app state, and it survives session stop and reload.
4. The UI is bounded by t3code's **closed catalog** of t3code-owned components; the agent cannot restyle or overlay the app.

## 3:30–4:00 Portability
- The same agent output renders natively in Buzz (Tauri/Flutter) and Paseo (React Native), and in CopilotKit apps. It's one skill, generated by `@a2ui/agent` `SkillGenerator`.
- Close on the PR diff size (target ≤ ~600 LOC, mostly the component map) and the e2e test running green.
