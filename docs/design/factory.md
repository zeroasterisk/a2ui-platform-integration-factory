# Factory design (draft for review)

## Pipeline (same for every host)
1. **Agent side: one skill, generated by upstream.** `SkillGenerator(new ExpressFormat([basicCatalog])).generateSkill()` from `@a2ui/agent` produces the Express contract plus catalog docs (about 22 KB, 277 lines). Each host installs it in its own way (Paseo plugin skill, t3code AGENTS/skill snippet, Buzz `BUZZ_ACP_SYSTEM_PROMPT_FILE`). The factory only owns the generation script. When TS macros land, macro catalogs flow through the same generator.
2. **Wire: what the agent emits verbatim.** Prose with `<a2ui>…Express…</a2ui>`, the upstream contract. The skill forbids ```a2ui fences, so hosts don't ask for them. Every host splits the **raw** message text before markdown rendering (t3code's rehype-sanitize would otherwise strip the tag).
3. **Compile happens at the render site:** `parser.parseResponse(text)` → text parts plus v1.0 JSONL parts. Proven in a browser bundle (`spikes/express-client`). Server-side compile is used only where the host already has a server hook (Paseo option A) or where a client can't carry about 300 KB (mobile, until measured).
4. **Render:** `@a2ui/web_core` `MessageProcessor` (root/state/processing subpaths) plus a host-native component map over the host's primitives. One map per UI stack (React DOM, RN, Flutter via `a2ui_core`).
5. **Actions:** the A2UI `action` is sent as a visible user message (thread reply on Buzz) carrying ```a2ui-action JSON. Local data-model edits stay client-side.
6. **Updates:** the same `surfaceId` in a later message, or a message edit, replaces the surface.

## Conformance (factory-owned, shared)
`conformance/demos/*.express` → expected JSONL + action round-trip transcript. Each host's e2e replays the same demos: form, checklist, choice, card list, live update, error fallback.

## Open decisions
1. Client compile vs server compile per host (default: client on web/desktop, server on mobile until Hermes is measured).
2. First host to build: **t3code** (web-only slice, fastest e2e via dev-replay) vs **Paseo** (original ask, needs RN + Docker mock).
3. Older surfaces after the thread moves on: live or read-only (default: live, with the busy guard).
